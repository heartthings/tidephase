# 每日题材情绪

收盘后做。涨停池约 15:15 落库，资金流约 15:20，个股日线约 15:30。早于这些时点，当天情绪不完整，不要出结论。题材和行业映射在每个交易日 08:20 刷新。看当天时，用当天已经生效的记录：`effective_from <= 当天` 且（`effective_to IS NULL` 或 `effective_to > 当天`）。不要把后来才出现的归属用到更早的日子上。

情绪定义以基础认知为准，不要另起一套阶段名。总纲：题材是舞台，情绪是推力。只看能形成聚集的方向。舞台是否还在，看筹码、消息新鲜度、趋势是否还在延续。

## 阶段（按基础认知，落在单个题材上）

用该题材成分股，不用全市场涨停家数代替题材。

- 聚集未完成：涨停家数明显变多，但还没有突破 3 连板的个股。这还不是启动期。
- 启动期：涨停家数在增多，并且出现突破 3 连板的个股。可以试错。涨停已经从高位掉下来时，不要因为还看得到 3 连板就叫启动期。
- 发酵期：涨停继续增加，连板高度到 4 到 5 板。
- 高潮期：涨停多，连续高度突破 6 板。投机情绪下持有的准备撤退，不追高格局，看不对了断臂止损。持续情绪下可以追高格局。
- 分歧期：涨停比前一日明显减少，或高位断板，或炸板变多。这时即使高度还在 3 板以上，也是分歧期，去弱留强。
- 退潮 / 冰点：涨停急剧减少，此前的高位股补跌，亏钱效应出现。

连板高度用日线算严格连续：当天涨停，且前一交易日也涨停，才往上加。`zt_pool.board_days` 是本轮累计涨停次数，中间可以夹着跌停，不能拿来当连板高度。

火热和冰点问的不是同一件事。冰点问这个题材还有没有持续性、还被不被看好。火热问这股推力还值不值得等。

途中下跌要同时有舞台、没有利空，才读成微调。缺一条就不是微调。利空已经打过题材之后的加速，只是反弹，不能格局。外部利空碰上已经开始的下跌，情绪会从犹豫走到一致看空。

## 哪些题材可以算

题材归属来自开盘啦 `GetConceptJXBKw23`，落在 `stock_sector_map`（`kind=theme`，`sector_code` 以 `801` 开头）。这是股票身上的标签，不是涨停原因。父子板块来自开盘啦 `SonPlate_Info`：子板块代码能对上成分股时，写成「父题材 / 分支」；股票只落在父板块、没有落在它的子板块上，写成「父题材」，不要把它说成某个分支。

`zt_pool.theme` / `reason` 是同花顺的涨停原因原文，经常一票一条，用来核对这批涨停是不是在说同一件事，不用它当题材分组的名字。

成分股多少不作为门槛。人多的标签和人少的标签都要分析，不能因为名字宽或人数多就丢掉，也不能因为名字像一个题材就认定它在聚集。

对每个涨停变多的开盘啦标签，打开当天涨停股的原因原文，看这些原因是不是在说同一件事：

- 多数原因原文就在说这个题材，舞台成立。人数多只说明标签大，不说明情绪是假的。
- 原因原文各说各的，或者最高板的原因第一句是别的事，这个标签只是口袋。情绪算到原因原文指向的那件事上，并写明口袋里混进了什么。
- 几个标签涨停的是同一批股票、原因也是同一句话，合并成一条，不要拆成好几个题材各写一遍。
- 原因里某个词只是附在别的主因后面，不把这个词单独升成舞台。

行业是另一列：`kind=industry`。行业和题材要分开说。一只股票可以同时有一个行业和多个题材。行业同样用涨停原因核对，不按行业名字直接下结论。

## 消息怎么对

评估的是这条快讯对题材的影响，不是对某一只股票的涨跌。个股快讯只有在它带动了整个题材时才写入，并且要写明它如何作用到题材上。

先用题材名、行业名在快讯标题里找最近几个交易日的原文。再用成分股名称搜到的快讯，单独判断：它有没有让这个题材的涨停变多、高度变高、或者让题材里的一批股票一起走弱。没有带动题材的个股公告，不写进题材结论。

- 写明时间、标题，以及它打在题材的哪一点（点着、降温、还是只碰到一只股票）。
- 对不上就写：没有对上打在题材上的消息。禁止编一条新闻，禁止把相邻题材的消息借过来。
- 快讯如果只是在复述盘面（「某某概念拉升」），它是结果，不是原因。原因要找它前面的产业、政策、订单、复牌、外盘消息。
- 外盘消息按基础认知里「外部情绪会不会带着 A 股走」来写，并说明这个题材当天有没有跟着走。

## 每条题材要写清

简报怎么写，由 F-029、F-030、F-031 决定。持续情绪写市场合力，投机情绪按主力来写。合力还是主力，看这一天的 K 线和分时，不按流通市值切。市值只是倾向：大票常常是合力，小票常常是主力，但同一天可以反过来。阶段、要看的个股、对上的消息都还要有。格局按情绪分：投机情绪不能追高格局，看不对了断臂止损；持续情绪可以追高格局，情绪初期和分歧时入场、做低成本。

先判断这一组是市场合力还是主力行为。同一件事上有一批票在同一时段一起封，分时是一波一波往上拱，这是合力，大票小票都算。全市场就这一只在讲这件事，或者 K 线是它自己的下跌、缩量、再拉，这是主力。一组里两种都有，分开写。

合力这一段要写市场为什么会聚到一起：舞台是什么，情绪的推力从哪来。是调整之后重新点燃，还是一致性已经最满、大家在兑现。没有对上的消息就写推力来自盘面本身。再写这波是谁带着谁，封板是挤在开盘还是盘中接力，高度有没有断。不把合力编成某一个主力的进出。

主力这一段必须写到这只票的日 K 和分时，按他的思考顺序：

1. 日 K 上筹码在哪一步。近几日是在跌、在缩量做低，还是已经连板，还是今天才放量起来。连板之后的日成交量中位数比首板当天更大（F-036），只有少数才是缩量。不要把连板写成量越来越小。
2. 分时上他今天为什么这样封。成交堆在开盘就把板封死、之后价格钉住，是把跟风的一致性封在涨停上。封住以后价格被砸开再封，是兑现和封板在对打。一字开盘且全天量缩小，是加速兑现，跟风接不到。盘中才放量封上，是这一段才动手，不是开盘抢的。看不出来就写看不出来，不要猜没有的分时。
3. 冰点问题材舞台还在不在。火热问这股推力还值不值得继续耗。游资看短情绪的加速和兑现，机构主力看筹码收集完之后的趋势，两套不要并成一种。

要看的个股点名代码和名称，只写它卡在上面哪一步：合力还在不在，或者筹码、兑现、舞台、推力。不写买卖点。

可能的发展和对应动作不写在每个题材下面，集中写进下一段。预演里的路径要和这一步对上：跳空和冲高里的兑现写成高开兑现；火热问还值不值得耗，写成分歧去弱留强或主线延续；尖叫、放量下跌写成放量下跌才入场；缩量阴跌写成不接。

输出用中文，先给三组：开始聚集、已经高涨、已经没有情绪。每组没有合格题材时直接写没有，不要硬凑。三组写完，先写「明日预演与应对」，再放次日首板/二板候选。

## 明日预演与应对（每日必写，只写这一段）

股市是应对，不是猜（F-006）。预演和应对写成同一段，不再分成两节，也不再单列「明日风险与观察」。每个题材下面已经写过的阶段、逻辑和个股，这里不重复。

这一段的顺序：

1. 第一条写 `**预期你的预期（给你的提醒）**`，按「明日提醒」一节选一档，用当日实际数字，不超过 3 行。
2. 接着只写今天的阶段和数字撑得住的路径。每条一行，路径和动作写在一起，点明落在指数上还是哪个题材上。没有依据的不写；一条都没有就写没有。
   - 高开兑现：今天已经放量上涨，或情绪档偏热。投机情绪：这是兑现，不是上车，回落时不补仓（F-024、F-031）。持续情绪：可以追高格局；做低成本优先在情绪初期和分歧，不把这次高开写成必须离场。
   - 分歧去弱留强：题材今天涨停减少、高位断板或炸板变多。投机情绪：问这股推力还值不值得等，不追高，看不对断臂（F-018、F-031）。持续情绪：分歧是入场和做低成本的时候。
   - 主线延续：舞台还在，涨停还在增加，高度没断。投机情绪：持有的看高度有没有断，不追高。持续情绪：可以追高格局。
   - 放量下跌、大家都在抛：近几日在跌，当天放量。投机情绪：大家都熬出尖叫才是入场条件，入场前慢慢确认（F-025、F-028）。持续情绪的入场在情绪初期和分歧，并做低成本，不把尖叫放量当成唯一入场（F-031）。
   - 缩量阴跌：在跌，但量没放大。动作：不接（F-025）
3. 最后用接口 `risk` 补两行具体名字，没有就写没有：高位断板观察、恐慌反手观察。盘中已经拉回去的大跌，写明次日不追（F-026）。持仓已经亏损并且确认做错：果断割，保住本金，这一笔结束（F-027）。上面的条件都没出现时写：慢慢等，没有踏空（F-020、F-028）。

不写点位，不写买卖价，不荐股。接口 markdown 里的「### 明日风险与观察」整节删掉，不贴进简报。

## 次日首板 / 二板预测

预测不是另起一套判断，而是把上面定出的题材相态，落到「明天哪几只票可能成为首板 / 二板」上。取数只走 data-api，禁止直连数据库，禁止本地重训模型。

调用：

```bash
GET http://127.0.0.1:8787/data/predict_limitup?date=YYYY-MM-DD&top_first=15&top_second=10
Authorization: Bearer <read token>
```

yan 环境读取 read token：`/home/hello/.qwenpaw/workspaces/guanshi/data/data_api_read_token`（只读，严禁写进输出、报告或飞书）。首跑约 60-90 秒，同一基准日、同一参数再调走 30 分钟内存缓存。`format=markdown` 直接返回可粘贴的正文；`format=json` 返回 `data` 全量字段（含 `markdown`）。token 严禁出现在输出、报告、飞书里。

json 返回要点：

- `as_of` / `next_trade_date`：基准日与下一交易日。`next_trade_date=null` 时写「下一交易日未知」，不要自己推。
- `market`：涨停、跌停、最高板、封板率、情绪档、今日首板数、昨日首板今日晋级率、上证涨幅。
- `first_board.groups`：今日未涨停、且符合技术形态的可能的一板，按板块分组。`first_board.sector_counts` 是每个板块有几只。不再输出二板候选，也不再输出风向个股。
- 每组：`theme` / `zt_today` / `zt3`（近 3 日涨停数）/ `height` / `phase` / `candidates`。
- 每只：`name` / `code` / `prob`（百分数）/ `reasons`（缩量后连续放量、急跌后放量上影、量比、上影、题材涨停数、首封、封单、炸板、主力净占比、涨停原因）/ `board_condition`。
- `risk`：`high_board`（3 板以上断板观察）、`chase_warning`（追高纪律）、`panic_watch`（恐慌反手观察）。
- `model`：训练/验证样本、基准、AUC、每日 Top10 命中率、同日排名分桶命中率。
- `gaps`：口径缺口，原样写进简报缺口段，不得省略。

写进简报的规矩：

1. 预测段放在「明日预演与应对」之后。标题写「次日可能的一板」。不要写二板，不要写风向个股。接口正文里的缺口段保留，不删。
2. 按板块分组，概率写在个股后面，并保留接口里的「板块只数」。接口 markdown 里的候选、情绪底座、模型可信度与缺口直接嵌入，不改概率、不重排、不按消息或板块热度删票。删掉其中的「### 明日风险与观察」整节，那些话已经写在「明日预演与应对」里。「近期预测兑现」里带了 `tape` 的几只，按原文嵌进去。那一段要看出题材持续度：近几日 K 线、兑现日分时、题材涨停家数是在增加还是接不住。不要收成「未涨停」三个字。概率低于 10% 的未中只留一行，不展开。
3. 概率读法：不是「必涨」，是同一交易日排名对应的历史晋级率（近 35 个交易日回算）。
4. 题材名来自开盘啦，并带父题材 / 分支。`zt_pool.reason` 只用来核对原因是不是同一件事。对不上就在口袋核对里写一句，不改接口给的题材名和概率。
5. 可能的一板仍用三条候选形态：缩量后连续放量上影、急跌后放量上影、连板后连续下跌跌出空间。这是收盘后的筛法，不是已经涨停的票常见的图形（F-036、H-004）。不因为没有消息、板块没热、或者题材到了发酵和高潮就把票删掉。板块只数按接口写。对得上快讯可以写，对不上就写没有对上的消息，禁止编新闻。不要补二板，不要补风向个股。
6. 不追加自己算的胜率、目标价、买卖点，不改概率，不挑票凑数；候选为空就写没有。
7. 这份名单不是买入清单。
8. 文字简报用 feishu-push 发出去之后，立刻运行 `python3 /home/hello/application/green/tidephase/tools/send_watchlist_images.py`。它只生成并推送一张「可能的一板」。不要再发风向个股，不要再发可能的二板，不要自己画图，不要改名单。同一天脚本若打印 `already sent`，图已经发过，不要再发。脚本失败就说明原因，不要假装图已发出。
9. 图发完后运行 `python3 /home/hello/application/green/tidephase/tools/limitup_verify_loop.py cycle`：先核对此前待验的首板/二板有没有涨停，写成 hit/miss 和反思；再把今天的候选落进 prediction 库。失败只说明原因，不阻断已经发出的简报。
10. 同一轮接着做下面的「个股涨停原因」。写完后紧接着再推一条飞书，标题「观势 · 涨停与跌停 YYYY-MM-DD」。不要留到 17:30，也不要另开定时任务。这不是反思，不写入 reflection，不写入迭代认知，不叫反思。

## 个股涨停原因（17:00 收盘同一轮）

跟收盘简报同一轮做完，17:00 推送。这不是反思，不写入 reflection，不写入迭代认知，不叫反思。

## 明日提醒：资金预期你的预期（写进「明日预演与应对」的第一条）

这条不是行情预测，是把 F-024/F-025/F-026 翻译成明天不要做的事。写在「明日预演与应对」的第一条，标题写 `**预期你的预期（给你的提醒）**`。不要再开一节「明日风险与观察」。下面「高开不是上车」只用于投机情绪。持续情绪可以追高格局，入场和做低成本在情绪初期和分歧（F-031）。

按今日状态选一档，用当日实际数字落地（上证涨跌幅、成交额或量比变化、涨停/跌停数、最高板、昨日首板晋级率），一句话结论 + 一句动作纪律，不超过 3 行：

- **一致恐慌档**（近 3 日跌≥8% 且量比≥1.2，或跌停显著增多、情绪冰点）：卖压释放完资金会反手买，但只有「放量 + 收在最低 20%」才算恐慌买点（T+1 +1.04%/63.0%）；缩量阴跌不买（T+1 -0.26%）。周五恐慌的买点在周一杀跌之后，不在周一开盘。

## 查询骨架

先看涨停变多的标签，不按人数过滤：

```sql
WITH mem AS (
  SELECT sector_name, count(*) n
  FROM stock_sector_map
  WHERE kind = 'theme' AND effective_to IS NULL AND sector_code ~ '^801'
  GROUP BY 1
),
zt AS (
  SELECT m.sector_name, z.date, count(DISTINCT z.code) zt_n
  FROM stock_sector_map m
  JOIN zt_pool z ON z.code = m.code
  WHERE m.kind = 'theme' AND m.effective_to IS NULL AND m.sector_code ~ '^801'
    AND z.date BETWEEN CURRENT_DATE - 8 AND CURRENT_DATE
  GROUP BY 1, 2
)
SELECT mem.sector_name, mem.n,
       coalesce(sum(zt.zt_n) FILTER (WHERE zt.date = CURRENT_DATE), 0) zt_today
FROM mem
LEFT JOIN zt USING (sector_name)
GROUP BY 1, 2
HAVING coalesce(sum(zt.zt_n) FILTER (WHERE zt.date = CURRENT_DATE), 0) >= 3
ORDER BY zt_today DESC;
```

连板高度不要用 `zt_pool.board_days`。点名之后，用这些代码在 `stock_daily` 上数严格连续涨停。然后把当天涨停股的 `zt_pool.reason` 打出来，看原因是不是同一件事，并对照开盘啦父题材 / 分支。龙头和资金、快讯按点名的代码、题材名再查。`round()` 对 `double precision` 要先转 `numeric`。
